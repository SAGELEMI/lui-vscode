# LUI 2.6.0 组件与插槽原始 RGBA 验收

日期：2026-09-06。入口：`node scripts/test-engine-component-parity.mjs <游戏根>`。原有 `scripts/test-engine-parity.mjs` 的八个标量状态夹具及输出目录保持独立。

## 当前结果

六组成对场景全部通过，原始 RGBA 的不同字节数和最大通道差均为 **0**。同时核对文本语义、组件内外层矩形、组件实例数量及内部引用隔离，不能仅靠两边同时显示空内容通过。

| 场景 | 具体证据 |
| --- | --- |
| 组件导入与调用处外壳 | 调用外壳为 300×140，外边距 4、内边距 12；组件根保持 132×92，内外层位置一致 |
| 调用方插槽作用域 | 内部标题为“组件内部标题”，插槽标题为“调用方插槽标题” |
| 重复实例隔离 | 两个相同组件有不同标题、底色和内部引用，各自保持独立 |
| false 数据 | 组件布尔属性显示 false，没有被默认 true 覆盖 |
| nil 默认数据 | 缺失绑定回退到组件声明的“组件默认标题”和 true |
| 单次绑定初始数据 | 两端以相同初始数据构造，标题和 false 保持一致 |

报告：`artifacts/engine-parity-components-20260906/report.json`。同目录保存每个样例的源标记、输入数据、投影 JSON、source/snapshot `.rgba` 和辅助 PNG。RGBA 为左下原点的 390×867×4 原始字节；PNG 只用于读图，不作为比较输入。已读图确认插槽标题来源及默认文字恢复。

## 两个修复与失败证据

初次有效夹具中，插槽源 Runtime 错把调用方的 `props['标题']` 解析成组件内部属性，产生 3909 个不同字节、最大差 207；快照投影把缺失输入写成 undefined，覆盖组件声明默认值，产生 3180 个不同字节、最大差 207。原报告及两组失败的 RGBA/PNG 保存在 `before-fix/` 子目录；修复没有改变通过阈值。

Runtime 现在为每个组件实例复制传入的 `slots.Content` 数组，附带调用方上下文。布局入口与直接节点入口消费内容时都使用这个上下文，因此 props、view、目录别名、重复项别名、引用和动作保留作者作用域。复制的是每次调用的数组，不向共享标记树写入上下文；多层内容呈现器继续逐层找回各自作者。外部手工提供的未标记 slots 仍按原有上下文处理。

快照投影现在在输入为 undefined/null 时保留组件默认值；false、0 和空字符串仍是有效输入。

## 验证条件与边界

- 沿用原八组夹具的同一 EnginePreviewHost、官方引擎、GL 上下文、字体和主题。实际环境为 DPR 1、NVIDIA RTX3060 / ANGLE D3D11、sRGB；精确引擎与 Runtime/字体哈希写入报告 identity。
- 每次请求严格匹配 sequence，等待至少 12 次布局，并在连续两次完成的 vendor RAF 回调后采集；第二次显示时间戳必须严格大于第一次。同一显示时间戳内若有多个回调，只保留最后一次，随后跨时间戳比较原始 RGBA，两次哈希必须相同。报告记录真实回调编号、时间戳和 `distinctDisplayTimestamps: true`。它们是分别采集的稳定静态状态，不宣称两端固定动画时刻同步；原八组标量脚本也使用相同要求。
- 标题实际区域要求至少 16 种颜色且含至少 50 个亮字形像素，本次每组为 244 色、1872 个亮像素；GL 尺寸、DPR、renderer、上下文属性及颜色空间必须一致。
- `tests/engine-preview.test.mjs`：4 项通过，增加 nil/null 默认值、false/0/空串、单次初始值与独立投影回归。
- `tests/runtime-slot-scope.py`：生产 Runtime 的多层插槽、仅调用方可见的组件目录、props/view/refs/actions、重复项隔离、实时更新、nil 默认及单次属性转发通过；覆盖两种 Slot 构建入口。Widget/Yoga 基础设施为替身，不能称为 GPU 验收。

单次绑定的后续数据变化由 Lua 回归验证；六组 RGBA 中的单次场景只比较同初始数据，未将重新创建的快照误称为保留了旧实例生命周期。这些夹具不执行游戏入口、不访问玩家存档，也不代替实际游戏业务和原生 VS Code Webview 交互验收。
