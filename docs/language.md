# LUI 语言规范

[返回文档入口](README.md)。适用版本：2.6.0。

动态 `可见性` 为 false 或“折叠”时完全退出布局，值为“隐藏”时只停止绘制和命中但保留位置。`画布.左/上/右/下` 和宽高可绑定，由同一 Runtime 正式排列，不应在业务代码中临时覆盖几何。相关坐标及测量接口见 [真实引擎预览](engine-preview.md)。

## 文件与语法

使用 UTF-8 和小写扩展名 .lui，同名后端为 .lui.lua。语言是受限 XML 子集，支持元素、属性、嵌套、注释与属性元素；不支持 DTD、外部实体、任意表达式或嵌入 Lua。属性中的 &、<、双引号使用相应 XML 实体。

根只能是页面或控件，必须声明名称。页面必须声明正数设计宽高；控件可自动测量。子节点可不命名。成对视觉标签可放子节点，底层控件内容能力见 [控件参考](controls.md)。

```xml
<页面 名称="Demo" 副名称="示范页面" 宽度="390" 高度="844">
  <容器 子项排列="垂直" 内边距="16">
    <文本 文本="你好，LUI" />
    <按钮 点击="{动作 Confirm}">
      <按钮.文本>确认</按钮.文本>
    </按钮>
  </容器>
</页面>
```

新文件使用中文语法。普通保存不格式化，显式格式化会规范属性名并处理同义重复属性。旧语法见 [迁移](migration.md)。

## 名称与路径

| 写法 | 作用与约束 |
| --- | --- |
| 名称="Demo" | 设计身份，支持中文，文件内唯一且与副名称不冲突 |
| 副名称="示范页面" | 可读设计身份，不会成为游戏文案 |
| 引用="StatusText" | ASCII Lua 访问键，对应 context.refs.StatusText |
| `{动作 Confirm}` | 查找 context.actions.Confirm，动作键为 ASCII |
| `{绑定 view.title}` | 读取当前视图模型，不执行表达式 |
| `{绑定 props['标题']}` | 中文键精确同名，对应 Lua `props["标题"]` |
| 目录:积木="Presentation/Components" | 根节点导入目录，别名支持中文且文件内唯一 |

绑定支持受限点路径和字符串索引，中文键推荐方括号形式。禁止函数调用、计算或条件表达式，改在 Lua 中计算字段。设计身份不是绑定路径。

按钮可声明 `背景`、`悬停背景`、`按下背景`。只声明 `背景` 时，Runtime 的各交互状态沿用该颜色，不让底层主题自行改色；需要品质或交互反馈时再显式提供另外两项。

## 目录组件

```xml
<页面 目录:积木="Presentation/Components" 名称="ComponentDemo" 宽度="390" 高度="844">
  <积木:操作卡 标题="准备完成" 确认="{动作 Confirm}" />
</页面>
```

目录相对游戏 scripts 资源根，必须匹配 lui.project.json 的 componentDirectories。操作卡是登记的公开名称，不要求与文件名相同。裸全局组件名、未登记别名、越界路径及循环依赖不能用于新项目。Registry 负责实例发现，componentDirectories 负责带目录别名的组件调用，二者不能互相替代。详见 [组件](components.md)。

## 条件与重复项

`<条件 条件="{绑定 view.showDetails}">`按预先计算的布尔字段构建内容。`<重复项 项目="row" 集合="{绑定 view.rows}">`按数组顺序展开模板，不增加容器。row 与 item 指向当前项，嵌套模板保留外层别名。

条件和集合在构建阶段求值，数据改变不会自动重建整棵树；刷新见 [绑定与事件](bindings.md)。

2.4.7：按钮新增 `文字左右对齐`（左／居中／右）和 `文字上下对齐`（上／居中／下），默认居中，支持属性绑定和属性元素语法。内部语义分别为 TextHorizontalAlignment、TextVerticalAlignment；使用范围及布局见 [布局](layout.md)。

## 2.5.0 外观与文字能力

标签能力由 `packages/spec/ui-capabilities.json` 和控件目录共同生成，Studio 属性栏、补全、诊断与 Lua Runtime 不再各自维护标签白名单。结构标签只显示结构属性；所有可视标签拥有背景、边框、圆角和不透明度，文字型标签还拥有字体、字号、字重、字体样式、颜色、行高、字距、换行、尾部省略和双轴文字对齐。

颜色只接受 `#RRGGBB` 或 `#RRGGBBAA`。线性画刷接受 `linear-gradient(角度deg, #RRGGBB[AA] 位置%, #RRGGBB[AA] 位置%)`；位置必须从 0 到 100 且前小于后。非法值会在设计诊断或 Runtime 构建时报出属性名称，不会静默换成主题色。

## 2.6.0 显式文字描边

仅 `<文本>` 支持 `文字描边颜色`（英文别名 `TextStrokeColor`）和 `文字描边宽度`（`TextStrokeWidth`）。颜色沿用上面的纯色格式；宽度为非负有限数值，单位是逻辑像素，不接受百分比或“自动”。两项均已设置且宽度大于 0 才启用；缺少任一项或宽度为 0 时关闭。它们支持普通属性绑定、单次绑定和绑定内的预览内容，属性栏归入“文字”组。非法字面量由语言诊断指出，非法运行时绑定值由 Typography 报出中文属性名。

```xml
<控件 名称="OutlinedTextExample">
  <文本 文本="获得奖励" 颜色="#F2EAFF"
        文字描边颜色="#10091C" 文字描边宽度="1" />
</控件>
```

动态写法例如 `文字描边颜色="{绑定 view.outlineColor, 预览内容='#10091C'}"` 和 `文字描边宽度="{绑定 view.outlineWidth, 预览内容='1'}"`。删除显式属性恢复无描边；普通文字及字重设置不会自动获得描边。不向容器或按钮标题继承这些 Text 专属属性。

原生 Widget 构造会把 `*Color` 字段转换为 RGB(A) 数组；Typography 同时识别该规范化结果，各通道必须是 0–255 的有限数值，省略 Alpha 视为 255。标记中的颜色字面量仍使用上面的十六进制格式。

描边复用 UrhoX Label 的八方向偏移描边，之后单次绘制正文，因此启用描边的文字不是总共单次绘制。默认正文仍保持单次填充，未恢复同色多次叠画的增粗补偿。描边不改变文字测量、布局或命中区域；需要为超出边缘的描边保留空间时应由作者安排周围布局。Studio 的结构示意仅近似表现，真实预览才使用上述原生路径。
